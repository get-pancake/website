"Paperclips" is how many people search for Paperclip, the open-source app that runs a team of AI agents as if it were a company. The project's own name is singular. Paperclip Labs publishes it at paperclip.ing and on GitHub as paperclipai/paperclip. Don't confuse it with Universal Paperclips, the 2017 browser game by Frank Lantz.

Paperclip belongs to a young category: the control plane for AI agents. This page explains what that layer does, the signs you need one and the signs you don't. Then it compares Paperclip with [Pancake](/), an AI GTM team, for readers whose real goal is customers.

**TL;DR:** Paperclip coordinates agents you bring. It assigns their work, wakes them on a schedule, caps what each one spends and logs every step. You need that layer once you run many agents across many jobs. Pancake does one job, which is pipeline. Its agents pick new leads from buying signals each morning and reach out to them from your own account. Pick Paperclip to manage an organization of agents. Pick Pancake if what you need is customers.

## What Paperclips (Paperclip AI) is

Paperclip is a Node.js server with a React dashboard, released under the MIT license in March 2026. As of September 2026 the repository has more than 82,000 GitHub stars. It shipped 15 releases between May 25 and September 21, 2026, roughly one every week or two. The README frames the idea with an analogy: an agent like OpenClaw is an employee, and Paperclip is the company around it.

You run it like a small firm. You write a goal. A CEO agent proposes a strategy and asks to hire more agents. You sit on the board and approve or reject each hire. Agents then wake on a schedule, which Paperclip calls a heartbeat, work their tickets and report up the org chart.

Paperclip ships no agents of its own. Its homepage states that no agents are installed automatically. You connect the ones you already use: Claude Code, Codex, Cursor, Gemini, Hermes, OpenClaw, OpenCode, Pi, a Bash script or any HTTP endpoint that can receive a heartbeat. One install can run several companies, with each company's data kept apart.

## What an AI company control plane does

The term comes from networking. A router's data plane moves packets, and its control plane decides where they go. Kubernetes uses the same split. Worker nodes run the containers, while the control plane decides what runs where.

Applied to AI agents, the agents form the data plane. They write the code, draft the post and answer the ticket. The control plane decides which agent works on what, when it works, how much it may spend and who has to sign off. Paperclip covers five jobs in that layer:

| Job | How Paperclip handles it |
|---|---|
| Assignment | Tickets with one owner, a status and a thread, plus goals that trace each task back to the company mission |
| Scheduling | Heartbeats wake agents on a timer, when a ticket lands on them, or when someone @-mentions them |
| Spend | A monthly budget per agent, a warning at 80% and an automatic pause at 100% |
| Approval | You act as the board, and new hires and the CEO's strategy wait for your yes |
| Audit | An append-only log of every instruction, response and tool call |

The control plane does not do the work itself. Paperclip adds shared skills and evals to help you train agents. The output still depends on the agent, the model, the prompt and the tools you connect. A good control plane makes a large team of agents manageable. It won't turn a weak agent into a good one.

## Signs you need a control plane

Paperclip's README describes its target user: someone with 20 Claude Code terminals open who has lost track of what each one is doing. If that sounds like your week, you are the user it was built for. Other signs:

- **You run agents in more than one function.** Paperclip's solutions pages cover engineering, support, sales and marketing, operations and finance.
- **You need hard spend limits per agent.** One model bill at the end of the month tells you nothing about which role burned it.
- **Public work needs a human yes.** Posts, emails and page edits wait at an approval gate, with a record of who approved what.
- **You run more than one venture.** A studio or an agency can keep each company's agents and data separate on one install.
- **Someone owns the org.** A person on your team writes the roles, connects the tools and reads the tickets every day.

The last sign matters most. The software is free. The org chart does not design itself, and governance means somebody reviews the work.

## Signs you don't need one

A control plane solves a coordination problem. Plenty of founders have a different problem.

- **You run one or two agents on one job.** The agent's own interface, or a plain task list, covers it.
- **Nobody has hours each week to supervise agents.** Board approvals, budgets and tickets only help if someone reads them.
- **Your bottleneck is an outcome no agent of yours produces yet.** If you need meetings with buyers, organizing agents you haven't built won't create them. You need the work itself, done well.

## Can Paperclips find you customers?

Paperclip's sales and marketing page pitches two kinds of agent. Research agents sweep competitor releases, pricing changes and industry news, then deliver a cited brief. Content agents draft posts and comparison pages in your voice. Anything public stops at an approval gate first.

As of September 2026, the page does not describe a lead database, a buying-signal feed or a prospecting workflow. Agents inside Paperclip can do outreach, but only with the data sources, lists and message logic you give them. For a founder who wants pipeline, that means building a sales function from parts before the first conversation happens.

## Where Pancake fits

Pancake is not a control plane, and it does not run a whole company. It is an AI GTM team for founders and small B2B companies. Its agents find people who show buying signals, run outreach for you and write articles built to show up in Google and AI answers.

Setup starts with your website. Pancake learns who buys from you (positioning, ideal customers, offers, proof and objections) and keeps it in one shared memory called the GTM Brain. It keeps learning from what works. Its agents watch six kinds of signal:

1. **Keyword:** people posting about a topic you choose, such as "ticket backlog".
2. **Competitor:** people engaging with a rival's posts.
3. **Influencer:** people engaging with a voice your buyers follow.
4. **Own brand:** people engaging with your own posts.
5. **Hiring:** companies with open roles that match your buyer.
6. **Stack:** companies whose job posts name a tool, such as one you replace.

New leads arrive each morning, and each one says which signal picked it. You approve leads in the app, or from Slack, where Pancake posts each new one. Outreach runs from your own account on the professional social network. The sequence is a profile visit, a like on a recent post, an invite with no note, then up to three messages. The opening message makes no pitch. It asks one light question tied to the signal. Pancake also writes articles for Google and AI search, and you approve each one.

The price is [$99/month flat](/pricing), with every agent included and no usage billing. The 3-day free trial needs a credit card, and you can cancel anytime. There is no org chart to design and no agent runtime to connect. Pancake does not send email, sync to a CRM or cover jobs outside go-to-market.

## Where Paperclips is the better choice

### You want to own the stack
The code is MIT-licensed. You can fork it, audit it and extend it with plugins. The Paperclip database runs on your laptop or on a server you choose.

### Your team already lives in agents
If your engineers run Claude Code or Codex all day, Paperclip organizes the agents you already pay for. Nothing gets replaced.

### You need agents beyond sales and marketing
Paperclip's own examples include coder agents that open pull requests, support agents that triage the queue and reporting agents that assemble the numbers. Each one gets a seat in the same org chart. Pancake has no role in that work.

### You want governance across many agents
Paperclip gives you per-agent budgets, board approvals, an audit log and separate companies on one install. All of it sits in one open-source dashboard you can read line by line.

## Where Pancake is the better choice

### The goal is pipeline, and you'd rather not build it
With Paperclip, prospecting depends on agents, data and outreach logic you assemble. Pancake arrives with the signals, the daily lead picks and the outreach sequence already wired together.

### You don't have hours to manage an agent org
Your daily work in Pancake is short. You approve the morning's leads and any new articles. That keeps you in charge of who gets contacted and what gets published.

### You want one fixed monthly price
Every heartbeat that wakes a model-based agent spends tokens on your model provider's bill, and budgets stop an agent at its cap. Pancake bills the same $99 every month, whatever the volume of work behind it.

## Can you use both?

Yes. A technical team can run coding and content agents in Paperclip and use Pancake for signals and outreach. Give each job one owner. If a Paperclip content agent already writes your blog, decide which system writes your articles so the two don't cover the same topics.

## The question that decides it

Do you want to run an organization of agents, or do you want more customers from the hours you have?

If it's the organization, Paperclip is a serious, active open-source project with a large community, and the software is free. Budget for model runs and for the time it takes to design and supervise the org. For setup steps and running costs in detail, read [Pancake vs Paperclip AI: setup, cost, and who each one is for](/blog/pancake-vs-paperclip).

If it's customers, Paperclip gives you the structure, and you still build the sales agents yourself. Pancake is that team already built, for one job, at one flat price.
